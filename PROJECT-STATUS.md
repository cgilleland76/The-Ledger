# The Ledger: project status and handoff

One repo (`cgilleland76/The-Ledger`, branch `main`) holds the website, the Netlify functions and the Android app.
Work from either Claude session starts here.

## Layout (single source of truth)
- `public/` is the web app and the only place the client is edited. `app-www/` is generated from it by `npm run app:build` and is gitignored.
- `netlify/functions/` (GM, portraits, billing, hero-save) serves the website and the Android app alike. A fix there reaches both at once.
- `android/` is the Capacitor wrapper. A phone keeps the `app.js` it was built with, so client fixes reach it only after `npm run app:sync` and a new build. Do that from a clean, committed `main`.
- `ANDROID-APP.md` (build and Play Store notes) and `NFC-MINIS.md` (NFC minis) cover the mobile side.
- Layer Line Tycoon is a separate project and lives in `C:\Users\chase\Documents\LayerLineTycoon`, not in this repo.

## Recently shipped
- Admin page and GOD view (`public/admin/`, `netlify/functions/admin.js`, `lib/admin-rules.js`, SQL `supabase/admin.sql`, tests `tests/admin.test.js`):
  - At `/admin/` (not linked anywhere, `noindex`, no-store). The page holds no power: every read and write goes to `/api/admin` with the admin token in the `X-Admin-Token` header. The function compares it with `ADMIN_SECRET` in constant time; 10 wrong tokens in 15 minutes lock that IP out (hashed IPs in `admin_attempts`), each wrong try waits a second, and with no `ADMIN_SECRET` (or one under 32 characters) everything is refused. The token is kept in `sessionStorage` only. No CORS headers on the answers. The repo is public, so the path is not a secret; the token is the only protection.
  - Sections: Rooms, Characters, Minis, Chests, Audit. Every tile is editable with Save / Reset and shows which fields changed. Saves merge only the changed keys into the stored JSON and are refused if one of those keys changed since the tile loaded (the tile shows yours vs now, with "Save mine anyway" or "Take theirs, keep my other changes"). Same value limits as the app (`checkPatch`). Pack items are edited as name + quantity and written back as "Name (3)"; chest contents as "3 Name". Typed-in items (`handItems`) are marked. A Raw JSON editor covers every other field. Every write is logged in `admin_audit` (deleted rooms keep a copy of their characters there).
  - Players see admin edits within about a second (the app reloads characters and the room on every change). If a player saves their sheet in that same second, the app writes its whole sheet and can overwrite the admin's change; edit again if that happens.
  - GOD view (Rooms → Enter as GOD): any table, including private, archived and paused ones. Not a member, no character, not counted in limits, spends no ink. Reads the table every 4 seconds through `/api/admin` (players' live updates are for members only). Post as GOD, Narrator, a system note or the GM; roll dice (written like the app's rolls); change HP or XP with a log line; edit any character; pause and resume. Pausing writes a log line and the GM refuses to answer (`rooms.admin_paused_at`, checked in `gm.js`). While the view is open the table shows a small "Watcher" badge (`rooms.watcher_at`, refreshed about once a minute); "Hide the Watcher badge" turns it off. A `?god=1` in a URL does nothing.
  - Not done (v2): acting as a character, triggering a GM turn on demand. The GOD log shows the GM's text unformatted.
  - `npm run app:build` leaves `public/admin/` (and `_headers`) out of the Android app.
  - Note: the brief mentioned public update rules in `schema.sql`; those were replaced by `accounts.sql` (tables are members-only) and are no longer on the live database.
  - To set it up: run `supabase/admin.sql` in the Supabase SQL Editor; add `ADMIN_SECRET` (long random value) in Netlify environment variables and redeploy; open `https://thedndledger.com/admin/` and bookmark it.
